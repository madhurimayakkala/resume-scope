# Resume Scope

A resume to job-description skill matcher. Upload a PDF resume, paste a job description, and see which skills match, which are missing, and what to fix first.

Scoring is **rule-based and explainable**. There is no AI model in the loop and no hidden weighting: the same resume and job description always give the same score.

Built with Next.js, React, TypeScript, Tailwind CSS, Framer Motion and pdf-parse.

---

## Features

* PDF resume upload with text extraction
* Skill extraction against a fixed skill list, with synonym normalisation (for example "JS" and "JavaScript" count as one skill)
* Frequency-weighted match score
* Matched skills and gap analysis, with gaps ranked as critical, moderate or minor
* Prioritised, rule-generated recommendations
* Built-in sample resume and job description for a quick demo
* Responsive layout, reduced-motion friendly

---

## How scoring works

1. **Extract.** Skills are found in the job description and in the resume by matching text against a skill taxonomy (`lib/skillKeywords.ts`) and a synonym table (`lib/synonyms.ts`).
2. **Weigh.** Each job-description skill gets a weight equal to how many times it is mentioned, capped at 5 so one repeated word cannot dominate (`lib/matcher.ts`).
3. **Score.** `score = matched weight / total weight x 100` (`lib/scorer.ts`).
4. **Rank gaps.** Skills you are missing are tiered by the same weight: 3 or more mentions is a critical gap, 2 is moderate, 1 is minor.

Worked example: a job description mentions React 3x, TypeScript 2x, SQL 1x, Docker 4x and CI/CD 2x. A resume with React, TypeScript and SQL has matched weight 6 out of a total of 12, so the score is 50%. Docker is a critical gap and CI/CD a moderate one.

**Limits.** Only skills in the built-in list are counted, and keyword overlap is not how any particular applicant tracking system ranks candidates. Treat the score as a way to see how well your resume covers a job description, not as a prediction of any employer's screening.

The "Summary" shown with results is assembled from a template using the numbers above. It is not generated by a language model.

## Tech stack

* **Frontend:** Next.js 14 (App Router), React, TypeScript, Tailwind CSS, Framer Motion
* **Backend:** Next.js API routes (`/api/parse-resume`, `/api/analyze`)
* **Resume parsing:** pdf-parse
* **Font:** Inter, loaded through the `@fontsource-variable/inter` package

## Project structure

```text
app/
  page.tsx               landing page
  analyze/page.tsx       upload, job description and results
  api/analyze/           skill matching and scoring endpoint
  api/parse-resume/      PDF text extraction endpoint
  globals.css            design tokens (colours, text, accent) and base styles
components/              UI components
lib/                     matcher, scorer, synonyms, skill list, recommendations
types/                   shared TypeScript types
```

### Design tokens

Colours live in one place: the CSS variables at the top of `app/globals.css`. `tailwind.config.ts` exposes them as classes such as `bg-surface`, `border-line`, `text-ink-muted`, `text-accent` and the result scale (`text-good`, `text-critical`, `text-moderate`, `text-minor`). Change a value there and it updates everywhere.
